# DAVE v1 signaling, media and verification

Recorded **2026-10-18** after `38445ca`. Official current sources were
verified **2026-10-18**, with exact bytes and hashes in
[the source record](../dave-current-sources.json). Official libdave is pinned
to [`8de72b1f8a2ac3c5a5270755bb8091a62e3c6169`](https://github.com/discord/libdave/tree/8de72b1f8a2ac3c5a5270755bb8091a62e3c6169).
Negotiated DAVE wire version **1**, MLS **1.0/ciphersuite 2** and Voice Gateway
**v8** remain explicit and distinct from the whitepaper revision. Upstream grouped
announcement/effective dates are unknown. Discord's separately announced eligible
voice E2EE requirement effective **2026-03-01** is not the local introduction date.

Previously Voice admitted opaque DAVE envelopes and suspended media, and the
independent MLS product supplied group key establishment. There was no owned
DAVE media/session backend. The independently adopted `DiscordDAVE` product now
provides authenticated external-sender/membership admission, proposal and selected
Commit/Welcome coordination, ready/execute and initialization transitions,
fresh-package recovery retaining the shared signing identity, exact Voice identity
binding, and active/pending/ten-second retired media epochs. Version zero and
unsupported protocol changes fail closed; there is no transport-only fallback.

Sender domains use the specified MLS exporter and forward HashRatchet, one shared
actor-owned counter, truncated AES-128-GCM tags and canonical synchronization
nonce/clear-range framing. Bounded failed/total verification accounting, replay
windows and timed key expiry are enforced independently. Opus, VP8, VP9, H264,
H265 and AV1 have real codec-aware encoded-frame transforms. Unsupported H264 VCL
profiles reject rather than disclose media; AV1 rewrites the final retained OBU
even when dropped padding followed it. The decryptor remains codec independent.

Pairwise scrypt fingerprints and decimal codes are implemented, with bounded
ephemeral account-scoped verification state across related sessions. Only an
application-confirmed out-of-band comparison marks a key verified. Key changes,
disappearance, disconnect/recovery and cross-session inconsistencies invalidate
that status. No verification UI, persistent identity storage or automatic trust
is implied.

[DAVE ownership and limits](../../DAVE.md) documents APIs, concurrency admission,
clock/resource bounds, nonce sharing, retry behavior and cleanup. Existing
HTTP/Gateway/Client/Cache/OAuth/umbrella products acquire no DAVE dependency.
DAVE depends on Voice/MLS/VoiceCrypto and existing Crypto/CryptoExtras; Voice and
VoiceCrypto retain independent adoption. No package version, native SDK or
external runtime dependency is added. Existing Voice consumers migrate by
explicitly selecting DAVE and composing its returned controls/media transforms;
no supervised connection is created automatically.

The original implementation followed the whitepaper's MLSMessage-wrapped opcode
26 sketch. The [2026-10-19 correction](2026-10-19-dave-keypackage-wire.md) supersedes
that representation after tracing the complete Discord.js/Davey Voice send path
and reproducing the mismatch with a native strict KeyPackage decoder. Opcode 26
now uses bare TLS KeyPackage bytes, matching pinned libdave. Live service acceptance
remains unverified. The implementation does not probe alternate encodings or replay
an ambiguous mutation. AES-GCM's documented lack of key commitment across retained
transition keys remains a known protocol property; no stronger guarantee is claimed.

Synthetic local peers and malformed/tamper/replay/counter fixtures validate owned
behavior. Independent algorithm evidence includes Node/OpenSSL AES-GCM bytes,
published/pinned ratchet and verification vectors, and
[eight exact C++/Swift codec oracle comparisons](../dave-codec-oracle.json).
Those codec comparisons compile unchanged pinned algorithms with minimal owned
collection adapters, not the complete libdave client. The [validation record](../dave-validation.json) records 1,976 passing root
tests and the complete tooling/offline-consumer checks. All evidence is local and
offline; no live Discord request, audio permission or device access is required.

Independent cryptographic/backend timing review, complete-client interoperability,
approved Discord media smoke, non-macOS/minimum-OS device qualification and
ten-minute hardware duplex remain open. Supervised join/network, SSRC routing,
RTP/media pipelines, playback/recording and video providers/packetization require
separate implementation and qualification evidence. Protocol support does not
constitute production, full voice/video, all-platform or fleet qualification.
