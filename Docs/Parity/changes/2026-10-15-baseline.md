# 2026-10-15: discovery and feasibility baseline

Recorded and verified **2026-10-15**. Upstream announcement/effective dates: **unknown** unless individually evidenced in
the feasibility reports. This is the first local inventory, not Discord's introduction
date for any inventoried feature.

The discovery baseline records architecture, concurrency and dependency policy,
a versioned inventory and schema, offline validation, platform capabilities,
per-method SDK contracts and unresolved ambiguities. Protocol choices are explicitly REST v10, Gateway v10 and Voice Gateway v8.

Source snapshots have pinned revisions/content hashes. Written docs take precedence
over the official preview specification. Stable and preview schemas remain separate
discovery evidence so contradictions cannot silently become implementation behavior.

Separate, locked development packages exercise macOS NIO HTTP/TLS/WebSocket/UDP and
public Swift Crypto/CryptoExtras primitives. They do not add production dependencies
or implement a Discord adapter, DAVE, MLS, codec or native SDK wrapper.

All inventory entries begin unsupported. No public symbol/payload behavior is added,
deprecated or removed, and no consumer migration is required. Full schema review,
multi-host transport qualification and missing upstream contracts remain explicit in
[coverage](../coverage.md), [platform support](../../PlatformSupport.md),
[transport findings](../../Feasibility/PlatformTransports.md),
[voice primitives](../../Feasibility/VoicePrimitives.md) and
[SDK contracts](../../Feasibility/PlatformContracts.md).

Official evidence: [API versioning](https://docs.discord.com/developers/reference#api-versioning),
[Gateway](https://docs.discord.com/developers/events/gateway),
[voice](https://docs.discord.com/developers/topics/voice-connections),
[change log](https://docs.discord.com/developers/change-log), and the
[pinned specification policy](https://github.com/discord/discord-api-spec/blob/ed014089afa986f2b532ae081c456a85de074d0c/README.md).
Support changes must append new history entries rather than rewriting this baseline.
