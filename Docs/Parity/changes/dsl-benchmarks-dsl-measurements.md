# Local DSL measurements

The unpublished 0.15.0 candidate adds local measurement tooling on 2026-10-18.
Upstream announcement/effective dates are unknown because no Discord wire contract,
endpoint, event, permission, intent, model or support classification changes.
Existing official-source review records continue to govern the composed contracts;
this change performs no new upstream collection or semantic protocol review.

Previously the existing cache/broadcast workload measured finite cache recovery and
broadcast ownership. It did not execute DSL handlers. The independent development
package now compares direct handwritten command routes with real typed DSL lowering
through the same decoder, handler, router and response owner. Separate external
manual/macro consumers measure clean consumer and incremental compiler work.

Measurements are recorded before finite numerical budgets are derived. Hard gates
cover schema reuse, finite input/state bounds, exact responses, zero implicit REST
work and zero owned activity after cleanup. Hardware/compiler/workload identity and
complete matrix checks prevent comparing unrelated reports. Accounted state, actual
RSS and live allocator gauges are distinct observations.

The existing 30-minute cache/broadcast soak and the new fixed-working-set handler
workload retain separate artifacts and actual durations. Local synthetic results
make no production/fleet, live Discord, other-platform, hardware, full supervised
host-throughput or independent crypto/interoperability claim. Release validation has its own report. Runtime products acquire no benchmark dependency
and existing public runtime APIs need no migration.

See [measurement scope and reproduction](../../DSLBenchmarks.md), the independent
[benchmark README](../../../Tools/DiscordDSLBenchmarks/README.md) and
[current validation record](../../Release/dsl-benchmarks-validation.json).
