# Reviewed inventory and deterministic generation — 2026-10-16

Local support date: **2026-10-16**. Release and commit: **unknown** (unreleased).
Upstream REST/Gateway: **v10**; Voice Gateway: **v8**, unaffected by this work.
Upstream announcement/effective dates: **unknown**. No new upstream feature or
operation is inferred from this local tooling change.

Previously, the discovery schema tracked broad source membership and implementation
status. Handwritten partial User/Application projections and three typed descriptors
had file-name evidence, with no reviewed field graph or generation drift check.

The reviewed catalog adds a separately versioned reviewed inventory with pinned revision/hash
references, stable field/model/enum/variant/endpoint IDs, real source declarations
and named Swift tests/structured fixture cases. The schema also links handwritten
event contracts to payload models and variants, with synthetic tooling tests and no
new supported Discord event. Field contracts explicitly retain
optionality, nullability, defaults, constraints, access and unknown-value handling.
Source verification and upstream dates remain distinct from local support dates.

The existing partial User/Application response projections and current-user/current-
application descriptors now have committed deterministic generated structure.
Bounded lossless JSON helpers, rate admission, retry decisions and the Gateway
discovery/runtime lifecycle remain handwritten. Unknown numeric lexemes, absent/
null/value distinctions and redacted diagnostics retain their existing contracts.
No REST operation is promoted to greater support because its source is generated.

Offline `inventory validate`, `generate --check` and `parity check` reject incomplete
or unclassified records, unresolved links, source pin drift, stale verification,
orphan symbols, nonexistent evidence and generated byte drift. `generate --write`
is the only writing mode and uses a fixed output allowlist. Consumer builds fetch
nothing and do not execute development tooling. Generated documentation is reviewed
structure; named evidence still requires meaningful assertions and execution.

Current counts derive from validated records in the
[generated reviewed report](../generated-reviewed.md) and nonwriting `parity check`
output. Discovery and reviewed totals are separate; overlapping written/preview
definitions are not unique Discord operations. Historical discovery counts remain
dated in the [coverage record](../coverage.md).

## Compatibility and migration

Existing consumer calls and partial payload behavior are preserved. Maintainers
edit reviewed definitions and handwritten helpers, explicitly regenerate, review
the resulting source/documentation diff and run root plus tooling tests. Direct
edits to generated output fail the next check. Unknown inventory metadata keys now
fail instead of being silently ignored; opaque upstream `definition` objects retain
their source-specific content. Historical reproduction uses an explicit audit date
without claiming current API currency.

[reference](https://docs.discord.com/developers/reference),

other-host runtime qualification, distributed coordinator or sustained-capacity gates.

completed local checks.
