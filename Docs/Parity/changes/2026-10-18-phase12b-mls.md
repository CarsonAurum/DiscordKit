# MLS 1.0 suite-2 key establishment

Locally added 2026-10-18 after `78d3703`. Current official sources were verified
2026-10-17/18 and their retrieved fingerprints are in
[the source record](../phase12b-current-sources.json). MLS 1.0 is RFC 9420
(July 2023), HPKE is RFC 9180 (February 2022). DAVE's selected wire version remains
1, distinct from the whitepaper revision and Voice Gateway v8. Upstream grouped
announcement/effective dates are unknown; the separately documented 2026-03-01
non-E2EE enforcement date is not a local MLS introduction date.

Previously no MLS code was implemented. `DiscordMLS` now independently provides
bounded canonical encoding, basic credentials, signed leaves/key packages, P256
HPKE/signatures, labeled hashes/KDFs, epoch schedules/exporters, secret trees,
ratchet trees, TreeKEM, tree/parent authentication and public group handshakes.
The DAVE v1 group policy requires the exact trusted external sender, eight-byte
big-endian participants, external Add/Remove proposals and cached reference-only
commits. Tentative state changes only after delivery-service selection. Welcome
validation authenticates the complete candidate before consuming its package.
Removal closes obsolete keys even when a new package for the same user reuses
its leaf index. Reset/recovery uses a fresh package owner.

[MLS ownership](../../MLS.md) documents APIs, participant authorization, counters,
limits, cancellation and cleanup. The [crypto review packet](../../MLSCryptoReview.md)
documents owned constructions, timing/usage-limit analysis and the required
independent review. Existing transport/truncated AEAD algorithms are unchanged.
No external package, native MLS implementation or Discord SDK was added. Existing
products do not acquire an MLS dependency; VoiceBot explicitly selects it.

Independent pinned MLSWG vectors cover primitive bytes, five chained key schedules,
secret-tree generations, signed key packages, contexts, every published suite-2
tree/TreeKEM case, transcripts and no-PSK passive Welcome composition. Generic
passive vectors intentionally bypass Discord-specific identity/profile admission;
they do not qualify the DAVE actor against a live peer. Synthetic local actors
cover multi-member agreement, concurrent candidate selection, replacement/removal,
revocation, malformed/tampered input, capacity limits and cleanup.

Independent external cryptographic review and other-platform/minimum-OS backend
qualification remain open. DAVE signaling, frame transformations, media sender
ratchets and supervised/live voice sessions belong to 12C/12D and remain
unimplemented. The reviewed group remains partial; passing local tests does not
constitute production crypto support or completion of every roadmap gate.
