# Channels and threads

Local implementation and verification: **2026-10-16**. API version: **10**.
No new dependencies.

Previously channel/thread routes and models were unsupported, with referenced
channel JSON preserved as partial message-family values. This change adds public
typed symbols for all 24 currently documented Channel operations and the guild
active-thread operation, complete channel-owned fields/variants, type-aware
settings, overwrites, forum/media messages and uploads, invite/recipient/status
requests, and membership/archive workflows. Referenced user/member/guild/app/
event/role family projections retain explicit partial classification.

Upstream chronology remains separate from local support:

- **2023-01-09:** Thread member details and opt-in pagination announced. API v10
  needs with_member=true; the announced always-paginated v11 behavior is future.
- **2026-04-20:** Voice status endpoint/permission/events officially documented;
  original introduction and effective dates are unknown. Status/start time are
  ephemeral Gateway data, not Channel fields.
- **2026-08-05:** Optional Channel application_id documented nullable; published
  availability says some channels can serialize null, with no separate effective date.
- **2026-08-12:** Channel obfuscation announced, effective **2026-11-16** for
  mandatory Gateway redaction and HTTP guild channel omission. Gateway testing can
  opt in before then; HTTP has no early opt-in. Preserve flags/redaction now without
  claiming the future HTTP transition already applies on the verification date.
- Other field/endpoint introduction/effective dates remain unknown.

Official sources verified 2026-10-16: [Channels](https://docs.discord.com/developers/resources/channel),
[Guild active threads](https://docs.discord.com/developers/resources/guild#list-active-guild-threads),
[Invite schemas](https://docs.discord.com/developers/resources/invite),
[API reference](https://docs.discord.com/developers/reference),
[change log](https://docs.discord.com/developers/change-log), and the pinned official
[OpenAPI specification](https://github.com/discord/discord-api-spec).
Current content hashes are independent of original discovery membership pins.

The current official specification revision
`ed014089afa986f2b532ae081c456a85de074d0c` fills numeric-status/authentication gaps
in the written reference: all three thread-start descriptors accept HTTP 201, and
group-DM recipient addition uses outer bot authorization with either a 201 Channel
snapshot or empty 204. Its recipient OAuth grant remains confined to the body.
The shared descriptor decoder receives only body bytes, so it validates either
recipient success shape without associating each body shape with a particular status.

Concrete written/preview differences remain in the
[ambiguity register](../ambiguities.json): preview-only alternate invite/typing
success responses do not broaden the written bot contracts. Invite approximate
counts and roles accept and preserve explicit null as a documented preview response
compatibility decision; this does not infer nullable requests or complete referenced
resource-family parity. No live Discord conformance is claimed.

Migration: opt into `ChannelEndpoints` and `ChannelOperations` in Models/HTTP,
provide channel-type context for edits and the user's gdm.join token for recipient
adds. Share credential-scoped rate/reuse authorities. Use timestamp cursors for
public/private archives and thread-ID cursors for joined-private archives. Use
withMember=true for v10 membership pagination; preserve complete thread/member
envelopes. No existing public symbol is removed or renamed. Historical message
partial projections remain source compatible; new Channel values can be decoded
from their exact raw data. See [contracts and limits](../../Channels.md).
