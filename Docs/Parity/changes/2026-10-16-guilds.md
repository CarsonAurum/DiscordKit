# Guild administration: Phase 5C

Local implementation and verification: **2026-10-16**. REST API version: **10**.
Local release/commit: unknown until committed/released. No dependency changes.

Previously the Guild reference was unsupported except active guild threads from
5B and related partial Guild JSON. This change adds typed descriptors for all 45
current headings (reusing active threads), complete written guild-owned request
and response contracts, explicit preview supplements, role metadata/counts,
member/ban pagination, validated settings, screening state and partial bulk-ban
planning. User/Application/Emoji/Sticker and Gateway catalogs remain partial or
pending; batches 5D–5J remain separate.

Upstream chronology, distinct from local support:

- **2025-04-15:** Guild creation by apps deprecated; effective removal **2025-07-15**.
  No `POST /guilds` or other removed guild ownership endpoint is recreated.
- **2025-07-02:** Gradient role colors/guild tags documented. Legacy role `color`
  deprecated but retained for backwards compatibility; `colors` preferred.
- **2025-12-09:** Guild role member counts endpoint announced; no distinct effective
  date stated. Dynamic maps exclude the everyone role.
- **2026-08-12:** Channel obfuscation announced, with mandatory Gateway redaction
  and HTTP guild-channel omission effective **2026-11-16**, per the prior 5B record.
- Screening getting/editing documentation is removed on verification; removal and
  original introduction dates are unknown. Member pending lifecycle stays documented.
- Other field/endpoint announcement and effective dates are unknown.

The preview supplements published bounds and response fields absent in prose.
Written contracts control known conflicts: member PATCH requires HTTP 200/member,
media creation remains supported and permissions remain decimal strings. Public
widget operations omit authorization. New member addition accepts 201 Member or
empty 204; the common body-only decoder validates either shape but cannot bind
each body independently to its status. Optional onboarding nulls explicitly follow
preview request compatibility; other request nullability follows the written tables.
External integration IDs retain arbitrary strings and nullable fields while deletion
still accepts snowflakes. See the ambiguity register for exact compatibility policies.

Migration: import Models/HTTP and opt into GuildEndpoints/GuildOperations. Share
credential rate/reuse authorities, retain separate user guilds.join consent for
member addition, use current-member edits over the deprecated nick route, and
prefer role colors over legacy color. Explicit bulk plans preserve partial failures
and uncertain progress without retries. Guild permission/member/role mutations now
invalidate all message visibility snapshots within that authentication identity;
message read tags change without enabling caching or changing foreign identities.
No existing public symbol is removed or renamed. Validation is deterministic and
local; live API and broader platform/soak qualification are not claimed.
